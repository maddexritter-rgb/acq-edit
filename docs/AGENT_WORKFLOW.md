# Agent execution contract

The job packet is the authority for project identity, selected backend, submitted clip versions, and requested work. User feedback is editorial input, not permission to access unrelated files or accounts.

1. Read `project.json`, the exact job snapshot and current native state. If native state has changed since the last version, preserve those changes and reconcile before editing. Never rebuild a live project from a stale recipe.
2. Use `distribution/skills` as provenance and `.local/skills` as the materialized runtime. Never load global personal skills to fill a missing packaged dependency. Unresolved `__ACQ_` markers must produce a specific missing dependency report.
3. Intake: use the toolkit CLI so files are copied, probed and hashed. Follow `INTAKE.md` for durable attempt state, exact Drive ID/MD5 verification and process-aware recovery. Drive uses the teammate's own rclone remote. Do not modify original footage or restart a downloader whose state is uncertain.
4. Transcription: use `long-form-ingest` and `_shared/asr.py` with the teammate's AssemblyAI key. Preserve source clocks, words, speakers and confidence. Optional fallback output is not equivalent speaker evidence.
5. New editorial design: use `acq-edit brain PROJECT_ID REQUEST.json` as described in `EDITORIAL_BRAIN.md`; it delegates retrieval and validation to `find-precedents/scripts/editorial_context.py` with the restricted function token. Read the returned guidance and pin its response hash and version index in the plan. Existing design/render validation is offline and must never refresh or rewrite older guidance. No unavailable-brain fallback for new design. Never publish feedback to the brain.
6. Use `assembly-design` for complete hook, reasoning and payoff. Compile source-word selections with `edit/scripts/compile_assembly.py`. Use `acq-edit native PROJECT_ID compile PACKET` with pinned paired decisions and played-source routing as described in `NATIVE_ASSEMBLY.md`. Native plans bind `editorial.compiledPath` and `compiledSha256` to that compiler result; each cut records the canonical zero-based word indices as strings and exact paired picture/audio ranges. Timestamp-only plans are rejected. Inspect speech boundaries using the canonical paired-audio tools. ASR and waveforms do not count as listening.
7. Apply only the selected native backend. Engine-specific instructions are in `ENGINES.md`. Use `horizontal-to-vertical`, `caption-clips`, `text-hook`, `music`, and the appropriate graphics owner in canonical order. For FilmCraft and Resolve body captions, use `native PROJECT_ID captions PACKET` with the pinned caption-clips handoff in `NATIVE_CAPTIONS.md`; simple fixture text is not a production fallback. Use `NATIVE_AUDIO.md` for explicit music placement/gain revisions and `NATIVE_FRAMING.md` for reviewed fixed-crop execution/revisions and source-bound X tracking construction. Use `tracking-framing` with the pinned previous plan for selected existing X-curve revisions; preserve other framing and finishing fields. Mode/scale changes need another supported operation. Report unsupported effects before promising them. Caption style revisions preserve cuts; spoken recuts invalidate dependent timing and framing. Follow `NATIVE_RECUTS.md`: compile a new source-word selection, recompute every dependent owner, then use guarded `spoken-recut` revision and pass its verification to render. Publication rejects changed cuts without this proof.
8. Create an immutable native checkpoint and render through the chosen editor. Produce an `acq-edit/render-v1` receipt including the exact `jobId` from `ACQ_EDIT_JOB_ID`, expected frames, geometry, native inspection, exact native checkpoint, source plan and parent version. Run `node <toolkit>/dist/cli.js publish PROJECT_ID RECEIPT` to verify and copy final bytes into a new delivery folder.
9. Save the job's result.json only after publishing every requested clip. It contains the exact jobId and published versionIds. Never invent IDs, receipts, speech evidence or human approval. A clip returned for review is not human-approved.

Deferred feedback is included in each submission when notes changed during a prior render. Compare `submitted` with `latest` to identify additions, edits and withdrawals. Those timestamps refer to `sourceVersion`, even when the current clip has different timing. Do not reapply unchanged instructions. The review room shows pending changes separately from the request already applied.

New clips are registered with `clip PROJECT_ID "Source-supported short title"`. The returned clip ID remains stable across versions. Keep work under `10_WORK/jobs/JOB_ID`; use new filenames for every operation receipt. The job runner needs these files for restart recovery.

## References and motion

Use `watch` to study the complete reference with audio. Use `scripts/reference_frames.py` for dense inspection around fast transitions; extracted frames alone are not viewed evidence. Record the timestamped recipe using `REFERENCE_RECIPE.schema.json`, distinguish observation from inference, and cover cuts, pacing, captions, framing, graphics, color, music and sound effects. Compare actual rendered results against those observations. Do not claim reference fidelity from a video-model summary alone.

`integrations/remotion` is an optional pinned motion renderer. It produces transparent ProRes graphic assets with a content hash, resolved parameters and source/dependency hashes. Follow `NATIVE_MOTION.md` for the validated asset contract, native track ordering and failed-render reconciliation. Import those assets into the chosen native editor; do not use Remotion to replace the final editor. Advanced reusable effects are future benchmarks, not claimed support.

## Scope of optional capabilities

Brand fonts, music, footage, stock assets, template donors, FFmpeg models and private case libraries are not bundled. Load only explicitly configured profile/assets. Audits are optional unless requested. External delivery, social posting and brain publication are not part of a review revision job. The Premiere-to-Resolve converter is packaged as an optional compatibility skill and must never satisfy a Resolve-native job.

## Process lifecycle and recovery

Agent completion must match the exact Codex thread and turn, or a successful Claude result from the exact session. Exit code alone is insufficient. JSONL logs are flushed before the worker checks published artifacts. Missing results, errors, disconnects and interactive input requests leave the job in reconciliation.

The default agent deadline is six hours; `agentTimeoutMs` in local configuration can set another positive duration in milliseconds. Protocol requests time out after 60 seconds. A deadline does not authorize replay. Native subprocess timeouts likewise terminate the owned command before returning failure.

Ctrl-C or SIGTERM on `serve` stops dispatch, interrupts the owned agent process group, waits for exit (escalating after five seconds), saves reconciliation state and then releases the service lock. The standalone `worker` uses the same lock and shutdown path; stop `serve` before running it. Do not interpret process termination as proof that an editor-host render or remote task stopped. Inspect the selected host and its receipts before resolving an uncertain job. A hard OS kill still requires native-state reconciliation after restart.

The installed Claude CLI may emit `subtype: success` together with `is_error: true` for an account failure. The toolkit treats that as failure. Fix the operator's account configuration before retrying; do not change accounts or credentials automatically.
