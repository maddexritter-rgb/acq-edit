# Installation and portable runtime verification

For the packaged new-Mac flow, start with [ONBOARDING.md](ONBOARDING.md). It installs a versioned user runtime and supplies the team reader; the source/developer recovery details below still apply.

Use a fresh checkout for a teammate installation or an upgrade. Keep existing projects and credentials in their configured external locations. The installer does not migrate project state. Onboarding registers skills in the toolkit project; personal discovery is an explicit optional install. See [skill discovery](SKILLS.md).

Resume saved review state with `acq-edit open PROJECT_ID`, then `acq-edit serve`. Resolve's explicit native reopening uses a prior inspection's identity/fingerprint packet; follow [RESOLVE_STATE.md](RESOLVE_STATE.md). Keep the existing native project database available. Review exports and DRP checkpoints alone do not silently replace a missing or manually changed native project.

The shared installer currently uses the `python3.11` executable. Install Node.js 24+, Python 3.11 and FFmpeg/ffprobe first, plus the selected agent CLI. YouTube and Drive intake additionally require `yt-dlp` and `rclone`; Drive authentication belongs to the teammate. Editor licenses, assets and agent authentication are separate setup steps.

Run the read-only prerequisite check for the selected engine before installation:

```sh
python3 scripts/install_engine.py resolve --check
# Or: premiere --check / filmcraft --check
```

Resolve checks for its bundled interpreter and shared executables. It does not require Cargo, Premiere or FilmCraft. Premiere adds npm. FilmCraft defaults to a pinned prebuilt runtime on Darwin arm64 with macOS 15.7 or later, without Rust or Xcode build tools. Preflight checks platform compatibility before large downloads. Other hosts receive an explicit limitation. For an explicitly requested `--source-build`, FilmCraft adds Git, Cargo, Rust 1.95+ and Xcode Command Line Tools; `xcrun` must find a compiler and SDK. It does not require Linux's `pkg-config` on a Mac. No mode switches to another editor. These checks do not prove agent authentication or native editorial quality.

The prebuilt archive is pinned in `release.json` by archive, manifest and executable SHA-256, source commit, architecture and minimum macOS. Extraction rejects traversal and links. Every installed file is verified on reuse; different or unreceipted files are preserved. Download/verification happens in a retained staging directory before promotion. The executable uses only macOS system libraries and keeps its original ad-hoc linker signature; Apple notarization is not claimed. Never disable Gatekeeper or managed policy to install it.

The packaging script `scripts/package_filmcraft_runtime.py` takes a clean pinned source checkout, its original build receipt, a locked `cargo tree -p filmcraft-cli --target aarch64-apple-darwin --edges normal --prefix none --format '{p}|{l}'` inventory and the matching Cargo registry source root. It checks the executable against the build receipt, checks architecture/system-library linkage and copies upstream notices, embedded-font notices, dependency license texts and corresponding MPL-covered sources. Missing registry license texts are retrieved at the crate's recorded upstream Git commit. The shipped manifest hashes every included file. Repackage only after reviewing the actual native build evidence.

The first prebuilt runtime was downloaded anonymously into an isolated installation on macOS 15.7.9 arm64. It exported and fully decoded a 25-frame H.264 test with 48 kHz audio; the saved timeline reopened identically except for transient clip selection. This is native runtime evidence, not clean-Mac, Gatekeeper, Intel, older-macOS or editorial acceptance.

After a successful explicitly requested pinned FilmCraft source build, the installer checks that tracked sources remain clean and that the executable can run `--help`. It creates a new immutable `.local/filmcraft-builds/<id>.json` receipt containing the source commit/origin, Cargo manifest/lockfile hashes, build command, Rust/Cargo versions, Apple tool paths, host architecture, selected build environment values, installer hash and executable size/hash. Repeat builds retain their earlier receipts. These are actual build inputs and outputs, not a claim of byte-identical reproducibility across hosts or native editing acceptance. System fonts and optional build inputs still require their own portable configuration.

## Repeating guided setup

`setup [backend] [agent]` loads the existing configuration before prompting. Enter keeps each current value, including storage, Python, selected-engine paths and brain configuration. Fresh configurations default to this checkout's shared Python and selected integration paths. `~` expands to the current user's home, and paths containing spaces stay intact. Setup configures paths; it does not install software or open an editor.

Advanced fields such as port, timeout and custom profiles are retained. Other configured editor paths remain available to existing projects. Default backend/agent changes apply to newly created projects; saved project identity, storage locations, sources, jobs and feedback are not migrated. An unchanged normalized configuration retains its original bytes and timestamp. A changed one saves the exact previous bytes under `config-history/` beside `config.json`, with mode 0600, before atomically saving the new configuration. Credentials stay in their separate file and are never rewritten by setup.

Custom agent executables are stored per agent in `agentCommands`. Setup migrates an existing `agentCommand` into the prior default agent's entry, preserving its effective command when selecting a different default. Enter `-` at the agent-executable prompt to use the standard command for the selected agent. The worker resolves the command for each project's recorded agent; a Claude project cannot inherit a Codex command merely because Codex is now the default. The legacy field remains supported for its configured default agent. A one-time migration creates a backup even if all prompt answers are blank.

Malformed JSON, non-regular configuration files and configuration changes made while the prompts are open are refused without overwriting the original. Setup uses the service reservation for saving and checks existing job/native/intake journals read-only. A running review room/worker or work needing reconciliation must be settled first; setup never clears an operation or declares it safe to replay. Stop standalone intake/native commands before reconfiguration as well. Cancelled prompts, Ctrl-C and EOF do not save partial answers. Use `-` at the brain-directory prompt to leave that feature unconfigured; doctor will report the missing requirement.

Actual terminal prompts created an isolated Resolve/Codex configuration, then a blank rerun preserved its bytes/timestamp. A subsequent FilmCraft/Claude default change preserved the existing Resolve project's database and manifest bytes, credentials, advanced settings and prior custom Codex command, with an exact private backup. No agent or editor was launched. Eight setup regressions cover all selected-engine defaults, cancellation/EOF, legacy-command migration, concurrent edits, active service/native/job refusal and immutable existing project identity. ## Health-check readiness

`node dist/cli.js doctor` prints one JSON report and exits 0 only when its required local checks pass. `readiness.blocking` identifies failures and repair steps; `readiness.optional` lists unavailable YouTube/Drive download tools without blocking local-footage editing. Missing or malformed toolkit configuration gives a setup repair and exit 1. Existing consumers can still inspect `skills`, `native`, credential-presence booleans and executable results; the new `dependencies` map provides stable check names.

Required checks cover macOS, Node.js 24+, FFmpeg/ffprobe, the configured Python and agent executables, accessible writable project storage, AssemblyAI/Gemini key presence, verified packaged skills, local editorial-brain configuration and the selected native adapter. FilmCraft additionally must run `--help`; a file existing at its configured path is insufficient. Resolve probes its supported Studio scripting connection. Premiere probes only its isolated toolkit connection. A failed skill-runtime check skips native and brain code rather than importing an unverified runtime.

The brain probe reuses the packaged reader's configuration and token-file rules. It checks the configured HTTPS editorial-search endpoint and matching project, and that a token is locally available. It neither contacts the endpoint nor verifies the token's remote validity or scope. Key values and raw configuration/connector exceptions are excluded from the report. Repair instructions retain the separate restricted-reader setup; do not substitute an administrative database key. Agent login/account credit, API quotas, live brain retrieval, source-media processing and human/native acceptance are listed under `readiness.unverified`.

Doctor creates no SQLite database, config folder, project or credential file. It does not change permissions, materialize skills, launch an agent session, fetch guidance or modify editor timelines. Python probes disable bytecode writes. Storage access checks do not reserve space or prove future capacity; verified intake still checks actual transfers.

A verified runtime is not proof that optional dependencies are present or the native workflow is qualified.

A repeat with the same source package, execution contract and assets verifies the existing receipt and every runtime file without overwriting them. Missing, edited or extra source files, an unreceipted runtime, or changed package/asset paths cause a specific refusal. Python bytecode caches are excluded from the source comparison. Older development runtimes, including v1 receipts that routed only the master skill, remain untouched; use a fresh checkout to adopt this installer. Changing the shared execution contract invalidates verification until a fresh runtime is prepared.

Cooperating installer processes serialize through exclusive checkout-local reservations. If a process is killed, inspect the PID in `.local/materialize.lock` or `.local/engine-install.lock` and confirm the original process has terminated before manually reconciling that exact reservation. Failed staging directories are retained. Do not delete a reservation merely because installation appears slow. There is no automatic stale-lock takeover or in-place upgrade.

The FilmCraft installer refuses dirty checkouts, an unexpected origin or an existing checkout at a different commit before materialization/build. A failed clone or partially prepared Premiere installation is retained for inspection; a fresh checkout is the supported retry location. Existing Premiere panels and profiles are never replaced automatically. The shared Python environment installer is still a separate pip/venv step; the skill-runtime transaction does not make pip installation atomic or fully lock transitive Python dependencies.
