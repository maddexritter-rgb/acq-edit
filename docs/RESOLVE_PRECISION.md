# Resolve native sample precision

Resolve Studio 21.1.1 build 10 now executes the shared paired-source audio plan with independent sample boundaries. It builds and renders entirely inside Resolve. No Premiere project, FilmCraft runtime, cross-editor conversion, flattened dialogue mix or UI click is required by this route.

## Construction

1. Validate the canonical source-word design, paired decisions, source routing and file hashes using `NATIVE_ASSEMBLY.md`.
2. Import picture and played PCM sources through Resolve's native API. Construct a new timeline with linked frame-aligned placeholders and verify their ranges.
3. Export that new timeline as a native DRT checkpoint. `resolve_precision.py` verifies its exact archive version, source paths, clip count and placeholder ranges.
4. Create a second DRT, changing only each dialogue clip's native `Start`, `In` and `Duration` fields to the paired sample positions. Every other archived byte is retained. The first checkpoint is immutable. Resolve stores fractional frames as an integer plus a little-endian floating fraction; the helper uses rational frame/sample conversion before writing that fraction.
5. Import the new DRT through Resolve's scripting API. Read back exact picture/audio ranges, source paths, source-clock agreement and native link membership. Errors greater than 0.001 sample are refused. Verify output geometry before any finishing.
6. Apply native Fusion framing/captions, music and graphics to the imported timeline. Save a new DRP and render using Resolve.

The adapter emits a pre-import precision proof and a separate successful native-readback proof. Neither grants editorial approval. It never patches an existing user timeline or its saved project. The DRT is generated by the teammate's own Resolve instance for this job; no prebuilt native project template is bundled.

This native archive format is version-specific and is not presented as a vendor-supported public file-editing API. The precision route is gated to Studio 21.1.1 build 10 and archive schema 17. A different host/archive fails explicitly until qualified. Ordinary frame-aligned construction still uses the native append API. Future host support needs independent source/range/link/readback and render testing.

## Why this path exists

`AppendToTimeline` preserved fractional record positions but rounded source trims and duration in testing. Direct OTIO import also rounded the sample ranges. `InsertAudioToCurrentTrackAtPlayhead` preserved source samples once an audio track was selected, but that UI dependency does not meet unattended execution needs. Those probes informed the native-checkpoint route; none silently substitutes rounded edits for the paired plan.

## Evidence

The synthetic 48 kHz / 25 fps source used the same two spans as the FilmCraft fixture:

| Span | Source samples | Timeline samples |
|---|---|---|
| 1 | 11–48017 | 11–48017 |
| 2 | 96017–143989 | 48017–95989 |

Readback preserved both spans, continuous internal audio, the intended outer picture-only samples, unchanged 25-frame picture cuts and linked video/audio. Closing and reopening the dedicated project preserved ranges, sources, links, properties and inspected caption inputs. Raw Fusion export hashes changed across reopen; a fresh inspection and checkpoint were used without disabling stale-state guards. Stable semantic Fusion inspection remains separate work.

Resolve exported 50 H264/AAC frames at 640×360; full decoding passed. Decoded audio correlated 0.99949827 with the exact-sample reference. A caption-only revision changed the first caption to green while preserving the native sample ranges and link groups. Its successful video export contained 50 frames, the second caption stayed unchanged, and decoded audio was identical to the prior native render.

These are synthetic words, labels and tones. They do not establish complete phonetic word endings, real speaker identity, human listening approval, real multicamera behavior or overall pilot readiness. Mono played PCM, matching clocks and the canonical paired compiler's supported sample grid remain current constraints.

## Export-state recovery

An audio-only diagnostic exposed a native export-state problem: Resolve reported a completed H264 video job but wrote an audio-only MP4. Repeating the export settings did not fix it. Loading the built-in **H.264 Master** preset, then applying the exact job settings, restored video/audio export. The adapter now resets through that built-in preset and explicitly sets AAC and the plan sample rate.

Host completion is never the final check. Before any adapter issues a render receipt, shared validation requires one video stream, an audio stream, the planned geometry/frame rate/frame count, and a successful full decode. Failed artifacts remain available for diagnosis and do not receive a new success receipt. Publishing into the review room continues its independent artifact verification.
