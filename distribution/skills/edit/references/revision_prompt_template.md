# REVISION PROMPT TEMPLATE — the standard structure for EVERY revision handed to another session

Use this for any "apply these review notes to clip V_n → V_n+1" prompt. It encodes the revision LAWs and ships a
MANDATORY deterministic self-check (`revision_verify.py`) so the downstream session can't deliver until every note
is provably applied + nothing regressed. Origin: ThreeFunctions V4 bounced (skipped notes + filler regression +
false ending) because nothing checked the output against the notes before delivery. Don't write a revision prompt
that omits the §SELF-CHECK block.

## How to author a revision prompt (the flow)
1. **Build a notes file** `notes.json` from the review — one entry per cut, EXACT verbatim wording (never "tighten
   by ear"; judgment stays with YOU, the downstream session executes mechanically):
   ```json
   {
     "cuts": [
       {"remove": "phrase to CUT"},
       {"remove": "members or", "expect": "the 3 core roles"},   // remove + the resulting line that must appear
       {"expect": "a corrected/restored line that must be PRESENT"}
     ],
     "end_on": "the exact words the clip must END on",
     "filler_guard": true
   }
   ```
2. **Auto-generate the verify spec** (don't hand-write it — keep it in sync with the notes):
   `python3 __ACQ_SKILLS__/_shared/revision_spec_from_notes.py --notes notes.json --out spec.json`
3. **Fill the template below** and paste the spec into §SELF-CHECK.

## ⛔ HOW TO REVISE — READ FIRST (LAW 6b)
A revision is a SURGICAL trim of the PRIOR delivered cut — **NOT a re-cut from source.** Start from <PRIOR>'s word
selection and REMOVE only the spans below (word-span deletions snapped to silence). Do NOT re-pull boundaries from
raw / rebuild the EDL — that re-introduces filler the prior cut already removed and chops the clip. Every trim
verified by re-transcribing the cut tail (never trust ASR on a clipped word). Deliver LOCAL; NEVER push to Frame.io/Monday.

## 🔒 PRESERVE EXACTLY (LAW 6 — nothing un-noted may change)
- CAMERA layout (which ranges are split / Alex / guest) — spell it out from the shipped pixels, keep identical.
- Grade, reframe, music state, and every line NOT named below. "No note about it" = "comes out identical."

## ✅ WHAT THE PRIOR VERSION GOT RIGHT — keep, don't touch
<list the things already correct so they don't get re-done/regressed>

## 🔴 THE CHANGES (exact, verbatim — one per note)
<for each: the exact words to remove / the exact resulting line ("READS AS") / or the caption fix. If a new caption
style is involved, include its MECHANISM (e.g. emphasis-quote = set words to {"c":"emphasis","q":true} = italic +
#FED90F + quotes). Give exact target text — no "tighten by ear".>

## ✅ §SELF-CHECK — MANDATORY before delivery (LAW 7; this is why prior versions bounced)
Run BOTH gates; a revision is NOT done until both pass:
```
# 1) did you apply EVERY note + not regress? (deterministic, paste the auto-generated spec)
python3 __ACQ_SKILLS__/_shared/revision_verify.py \
  --prior <PRIOR_BUILD>/w_norm.json --new <NEW_BUILD>/w_norm.json --spec <spec.json>
# spec.json (auto-generated by revision_spec_from_notes.py from the notes):
<PASTE THE GENERATED spec.json HERE>

# 2) mechanics/ending/loudness/seam gate on the rendered file
python3 __ACQ_SKILLS__/edit/scripts/reqc.py <delivered.mp4> --project <project_dir>
```
If `revision_verify` prints any ✗ (uncut note / missing target / leaked-or-false ending / filler that INCREASED
vs the prior cut), the revision is INCOMPLETE — fix and re-run until it exits 0. Do NOT deliver a ✗.
Then: audit-captions (color/casing/accuracy) + audit-audio + audit-visual on the rendered file.
Deliver to 20_DELIVER/<guest>/v<N>/. Show Maddex. WAIT. No external push.
